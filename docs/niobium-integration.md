## Registration, identity and errors

Application composition is in [Server.DependencyModule.AddInvoicing](../src/Niobium.Invoicing.Server/DependencyModule.cs) and [Core.DependencyModule.AddCore](../src/Niobium.Invoicing.Core/DependencyModule.cs). Framework `RegisterDomainComponents` discovers `IFlow`, domain and domain-repository implementations in the supplied assembly. Registration is generally transient; HTTP context access is singleton. Static registration guards make host reinitialization in the same process significant. No application-specific event handlers are declared.

At 4.0.61, [Identity.DependencyModule](https://github.com/niobium-nz/Niobium/blob/c2462746614ee6c768d725c99e3c54df2e3848c8/Niobium.Platform.Identity/DependencyModule.cs) composes bearer, access-token and resource-token middleware after platform context/error handling. [AccessTokenMiddleware](https://github.com/niobium-nz/Niobium/blob/c2462746614ee6c768d725c99e3c54df2e3848c8/Niobium.Platform.Identity/AccessTokenMiddleware.cs) verifies an ID principal, obtains Sid/GroupSid, reads roles and describes entitlements, then issues an access token in the response Authorization header. Bearer parsing by itself is not a universal requirement to authenticate every route.

[ResourceTokenMiddleware](https://github.com/niobium-nz/Niobium/blob/c2462746614ee6c768d725c99e3c54df2e3848c8/Niobium.Platform.Identity/ResourceTokenMiddleware.cs) parses `type/resource/partition/id`, asks controls for a grant and returns `StorageSignature`. [SignatureService](https://github.com/niobium-nz/Niobium/blob/c2462746614ee6c768d725c99e3c54df2e3848c8/Niobium.Platform.Identity/SignatureService.cs) uses a one-day expiry; access JWT validity defaults to eight hours. The application does not override these defaults. Controls and actual permissions are catalogued in [API/messaging](api-and-messaging.md).

At 4.0.60, [OwnershipControl](https://github.com/niobium-nz/Niobium/blob/1fa044968f504ef575021720c728a17dc72bb067/Niobium.Platform.StorageTable/OwnershipControl.cs) for `InvoiceItem, Invoice` checks whether an Invoice exists at the authenticated Sid partition and requested invoice row, then grants item-partition query access. Personalized descriptors use the user partition. SignatureService accepts the first non-null control grant; the registered default table control is another provider, so the custom ownership check is not a mandatory gate for every possible resource request. [AzureTableSignatureIssuer](https://github.com/niobium-nz/Niobium/blob/1fa044968f504ef575021720c728a17dc72bb067/Niobium.Platform.StorageTable/AzureTableSignatureIssuer.cs) requires an account key to sign SAS even when server-side table I/O uses managed identity.

The Q15 application change removes the InvoiceItem general entitlement descriptor and retains OwnershipControl, which does not require that descriptor. No framework composition or package version changes were made. Existing access-token claims and externally managed entitlements still need separate review; changing registration does not revoke credentials. InvoiceItem keys remain unchanged under Q16.

[ValidationHelper](https://github.com/niobium-nz/Niobium/blob/c2462746614ee6c768d725c99e3c54df2e3848c8/Niobium.Helper/ValidationHelper.cs) invokes `IUserInput.Sanitize` and DataAnnotations validation. C# `required` is a construction/deserialization constraint, not an amount, currency, ownership or nested-item validator. Requests/items have no comprehensive business validation attributes. [ErrorHandlingMiddleware](https://github.com/niobium-nz/Niobium/blob/c2462746614ee6c768d725c99e3c54df2e3848c8/Niobium.Platform/ErrorHandlingMiddleware.cs) catches Niobium `ApplicationException`, maps its numeric error to HTTP when in range, and writes JSON. It does not catch all Azure, JSON, culture, timezone or host exceptions.

## Domains and repositories

[GenericDomain](https://github.com/niobium-nz/Niobium/blob/c2462746614ee6c768d725c99e3c54df2e3848c8/Niobium.Abstractions/GenericDomain.cs) owns the entity/repository and optional event handlers. Building a domain from an entity does not mean loading the previously persisted entity. `InvoiceDomain` now uses ordinary conditional saves for preparation/freeze checkpoints. Force saves would follow create-with-replacement and are not used by this issuance path. Without force, GenericDomain chooses create for entities without ETag and update for those with ETag, then invokes entity-change handlers after persistence. Handler failure can therefore follow a completed write; no application handlers were found here.

[CloudTableRepository](https://github.com/niobium-nz/Niobium/blob/1fa044968f504ef575021720c728a17dc72bb067/Niobium.Database.StorageTable/CloudTableRepository.cs) uses `typeof(T).Name` unless overridden. `DBEntityHelper` maps key attributes and converts date keys to reverse timestamps. For create-with-replacement, a single entity uses Azure `UpsertEntityAsync` with its default Merge mode; batches use `UpsertReplace`. Calling it a complete unconditional replacement in every case would be inaccurate. Regular update/delete paths use ETags when precondition checking is enabled; `false` selects `ETag.All`. Local Azurite tests reproduce retained read ETags, missing write-result ETags and stale update rejection. The application reloads and verifies content when a write result lacks its ETag; see [recovery](invoice-recovery.md). Live Azure behavior remains unverified.

Batch operations group by partition and split at 100 actions. There is no transaction across partitions, tables or the invoice/item/queue stages. Despite `ExecuteBatchWithRetryAsync`'s name, do not infer a business replay protocol: transport retry settings belong to Azure SDK clients. Expiry on table creation is explicitly unsupported. No table creation, schema migration, retention worker or audit history is registered by this application.

The application passes cancellation to most repository/profile/broker operations. Some inherited methods omit it at subsequent boundaries (for example signature-control issuance and some async enumeration). There is no blanket cancellation/rollback guarantee. Inspect the complete call chain when changing this behavior.

## Finance, formatting and serialization

[Finance.Amount](https://github.com/niobium-nz/Niobium/blob/1fa044968f504ef575021720c728a17dc72bb067/Niobium.Finance/Amount.cs) stores `long` cents and a currency. Its converter emits an object with cents and currency; currency has its own string converter. `Amount.Zero` uses the default USD currency, though invoice update copies only its cents. Currency parsing supports more values than display formatting, which supports NZD, AUD, USD and CNY in the matched source.

[JsonMarshaller](https://github.com/niobium-nz/Niobium/blob/c2462746614ee6c768d725c99e3c54df2e3848c8/Niobium.Helper/JsonMarshaller.cs) defaults to camelCase, case-insensitive input, with no global omission of null/default values. Queue bodies use it through `MessagingEntry`. ASP.NET/Functions request binding is host-provided and is not proof that every serializer option matches queue serialization. See [wire examples](api-and-messaging.md) and [data mapping](domain-and-data.md).

## Profile and messaging

[ServicePrincipalProfileService](https://github.com/niobium-nz/Niobium/blob/1fa044968f504ef575021720c728a17dc72bb067/Niobium.Platform.Profile/ServicePrincipalProfileService.cs) uses `DefaultAzureCredential` for the configured profile audience and retrieves the biller from the external profile service. The app calls `IProfileService<Biller>.RetrieveAsync(tenant, biller)`; a local Biller table repository is not implemented here. Upstream profile storage and membership administration remain outside scope.

[ServiceBusQueueBroker](https://github.com/niobium-nz/Niobium/blob/1fa044968f504ef575021720c728a17dc72bb067/Niobium.Messaging.ServiceBus/ServiceBusQueueBroker.cs) selects a lower-case contract-name queue (`notifycommand`), sends JSON with `MessageId = MessagingEntry.ID`, and can attach an available bearer token as an application property. Invoicing's consumer does not validate that property. Azure SDK transport retries are separate from Functions redelivery and business idempotency. The development broker logs message content and completes without sending to a recipient; it does not make other dependencies local.

## Notification boundary

The relevant snapshot is [Notification commit 9481cc3](https://github.com/niobium-nz/Niobium.Notification/tree/9481cc3974f50440d6a32b02b8b1341590457218), matched to **Contracts 2.0.7**, not established as the deployed server revision. Targeted inspection covered:

- [NotifyCommand](https://github.com/niobium-nz/Niobium.Notification/blob/9481cc3974f50440d6a32b02b8b1341590457218/src/Niobium.Notification.Contracts/NotifyCommand.cs): sender tenant, channel, destination/display name, parameters and optional token.
- [Consumer](https://github.com/niobium-nz/Niobium.Notification/blob/9481cc3974f50440d6a32b02b8b1341590457218/src/Niobium.Notification.Server/NotifyCommandConsumer.cs): parse/validate, template-parameter conversion, dispatch; invalid input paths log and return.
- [NotificationFlow](https://github.com/niobium-nz/Niobium.Notification/blob/9481cc3974f50440d6a32b02b8b1341590457218/src/Niobium.Notification.Core/NotificationFlow.cs) and [TemplateDomain](https://github.com/niobium-nz/Niobium.Notification/blob/9481cc3974f50440d6a32b02b8b1341590457218/src/Niobium.Notification.Core/TemplateDomain.cs): template by sender tenant/channel, HTML parameter encoding, provider send; a missing template can return without sending. No invoicing delivery-confirmation callback or message-ID inbox is present in this path.
- [Queue declaration](https://github.com/niobium-nz/Niobium.Notification/blob/9481cc3974f50440d6a32b02b8b1341590457218/infra/service-bus.bicep): duplicate detection disabled.

The owner confirmed the cost rationale and planned downstream message-ID storage, with broker detection an option as usage grows (Q11). These changes belong to Notification/transport, not this documentation task. Neither a stable ID nor an isolated unique insert proves exactly-once recipient delivery across failures.

## Preserve these conventions

Use matched sources before changing registration order, resource controls, force-save semantics, key encoding, event metadata, serializers or retry behavior. Keep package references as packages. A dependency upgrade requires rechecking the resolved graph, these source pins and affected tests; there is no claim that latest main retains the same behavior.
